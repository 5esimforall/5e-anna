# 查询与阅读界面设计实现

查询界面围绕筛选、横向比较和原文核对组织。法术、生物、物品等各类条目共用工作台与阅读层，具体字段、筛选组和排序仍由服务端 schema 提供。

表的 schema 由所选的条目类型推出（`browse.schema_for`）。只选一类时使用该类自己的列、筛选组和排序；选择多类时以通用表（名称、类型、来源、规则版本）为底，按类型阅读顺序并入每一类的列、筛选组和排序，默认按类型排列。同时选择普通装备与魔法物品，表格因此显示普通装备的价格、重量、伤害、精通和魔法物品的稀有度、类别、同调；混合类型中覆盖条目最多的筛选组排在前面。未选类型即全部条目，使用通用表。

## 条件与计数

早先的左侧目录列出 25 个分类视图，常驻 188px。它回答的“用哪张表”在一次查阅中很少改变，却在阅读时也占着宽度：1440px 下打开条目后结果区只剩 500px。目录里的视图本身也只是筛选：每个视图是一组条目类型，另外六个（NPC、伙伴、坐骑、魔法武器、战斗风格、传奇恩惠）是一个类型加一个字段取值。之后一版把类型做成标题上的专用选择器，类型仍与其他条件分属两套操作。

现在所有筛选共用一个模型：查询是一组条件，每个条件是“字段 + 一个或多个取值”。

- 同一字段的取值取并集，不同字段取交集。名称搜索也是条件，每个搜索词各成一个条件，多个搜索词因此都要匹配（`browse.search_terms`）；匹配度排序依据正在输入或最近保留的搜索词。
- 类型（`type`）是筛选区的第一个字段，与环阶、来源等字段同样排版、同样操作，并同样以已选条件显示和移除。它另外决定表的列、筛选组和排序（`browse.schema_for`），标题写出所选类型或预设名，只作说明。
- 条件栏把全部条件显示为搜索框内的标签，输入位于标签之后。输入的文字即时作为名称搜索生效；按 Enter 把它留作标签并清空输入框，可以接着输入下一个搜索。每个条件、每个保留的名称搜索都是独立的标签，标签之间以“∧”连接，表示总是同时成立；同一字段内的多个取值写在一个标签里，彼此取并集。输入框为空时 Backspace 移除最后一个标签。
- 保留的搜索是页面状态，只在载入和前进后退时从 URL 读取；URL 以 160ms 延迟跟随输入，若从 URL 反推哪些搜索已保留，输入法连续上屏时上一段文字会被误当作保留的搜索。Safari 在合成结束后才送出确认合成的按键（`keyCode` 229），它不作为 Enter 处理。
- 输入时下拉列出可添加的条件：第一项是“名称包含……”（Enter 的默认选择），第二项是“正文包含……”，其后是标签或别名与输入相符的字段取值（类型、领域字段、规则版本、来源；核对模式下另含审核字段）及预设，按完全相同、开头相同、包含排列，同档按结果数排列，至多 8 项。上下方向键移动，Enter 或点击选择，Esc 收起。选择取值即把它加入所属字段，输入的文字不再作为名称搜索；取值旁的数字按不含这段文字的条件计算，与选择后的结果一致。
- 正文搜索（`body`，可重复）在条目标题之后的原文中按字面查找（与 `entry_layout.text_start` 同一起点），每个词各成一个条件；它只能从建议中添加，不随输入即时生效。
- 保留的搜索记为 `q`，正在输入的文字记为 `typing`，二者同样作为名称条件生效，匹配度排序依据 `typing`（没有时依据最后一个 `q`）。刷新或前进后退后，`q` 显示为标签，`typing` 回到输入框，仍待 Enter 保留。
- 每个字段、每个名称或正文搜索都可以排除：`not_<key>` 记录排除的取值或词（`not_type`、`not_f_school`、`not_q`、`not_body` 等），条件对不含其中任何取值的条目成立；未提取的取值不算含有，因此不被排除。点击标签文字在“是／不是”“包含／不含”之间切换，× 仍是移除；排除的标签以虚线框显示。范围（CR）、字段冲突开关和正在输入的文字不能排除。
- 筛选区中，字段只有排除的取值时处于排除模式：“排除”按钮按下，选中的取值显示删除线，勾选编辑排除列表；点击“排除”把整个字段在包含与排除之间切换，与标签切换相同。同一字段可以同时有包含与排除两份取值，各成一个条件。下拉建议总是包含所选取值，若该值在排除列表中则从中移出。标题在只排除类型时写作“全部条目（不含……）”。
- 字段未选任何值即不限制；点击取值即加入，再点取消。“反选”改为该字段中其余的取值，“清除”去掉该字段的条件；选中全部取值等同于不限制。工具栏的“清空”去掉全部条件（类型在内），保留排序与版本显示方式。
- 每个取值旁的数字是选中它之后的结果数：保留其他字段的条件，放下本字段的包含与排除两份条件，再数含有该取值的条目；排除模式下，这个数就是排除它会去掉的条目数。`serve.facets` 一次遍历完成：未通过任何条件的条目计入所有字段，未通过的条件都属于同一字段的条目只计入该字段。计数为零的取值变淡但仍可选择。类型的计数另外忽略该类型无法回答的类型专属条件，与切换到该类型后的结果一致。
- 改变类型时，类型专属条件（领域字段、CR 范围）只在所有所选类型都能回答时保留（`meta.type_conditions`）：在坐骑上加入法术，“使用角色：坐骑”随之移除，法术才会出现。直接打开的链接只移除新表没有的字段。
- 字段列表与取值在表不变时保持不变，计数就地更新，焦点和展开状态不因计数刷新而丢失；类型改变或范围内出现新的来源时才重建筛选区。来源的取值是所选类型中出现过的来源，加上已选取值。
- 在某些类型中搜索时，结果栏显示“其他类型另有 N 条”，点击展开筛选区并聚焦类型字段。结果为空时，空状态列出去掉后能得到结果的条件及结果数（`facets.without`），点击即去掉该条件。
- 名称搜索没有结果、但未分类段落满足同一组条件时，空状态显示“原文中还有 N 条未分类段落匹配”，点击后带上 `sections=1` 重查。`/api/entries` 的 `section_matches` 给出这个计数；有类型结果、正文搜索或已包含未分类段落时不提供该提示。
- 预设（`browse.PRESETS`）是一个类型加一个字段取值，每个预设与数据库中同名的 SQL 视图结果一致，由单元测试约束。生物的“使用角色”是生物字段。环境危害（`hazard`）作为独立类型出现在选择器中，排在规则之后；数据库的 `危害` 视图包含陷阱、毒药、疾病和环境危害。属性（`ability`）与技能（`skill`）排在状态之前，技能表以所用属性为列与筛选字段；两者与状态、动作一样按英文名叠放 2014／2024 版本，数据库的 `状态动作规则` 视图包含它们。
- `/api/entries`、`/api/facets` 与 `/api/export` 接受同样的条件参数；`type`、`q` 可重复。未知类型、`section`、超过 20 个或长于 200 字的搜索词返回 400。`/api/entries` 附带当前表的 schema。

旧的 `view` 参数在载入时移除，旧链接打开全部条目并保留其余条件。数据库中的 SQL 视图与 `views/` 下的 CSV 分类表仍按原分类生成，供 `query.py --view` 与审计使用。

## 视觉规则

查询界面同时承载两种内容：不全书本身的规则文字，以及 anna 从中提取、推断和核对出的结构。视觉规则让读者一眼分清两者，并把审核细节留给需要它的时候。

- 书的内容使用衬线字体：类型标题、条目中英文名、阅读栏标题与正文。工作台控件、筛选和表格数值使用无衬线字体。两套字体都取自系统字体栈（`--anna-serif` 与 `--anna-sans`），不引入网络字体。
- 字号分为几档（`--anna-type-*`）：中文界面文字不小于 13px，笔画在常见屏幕上不发糊；12px 只留给缩写、计数和英文名这类拉丁字母与数字；条目名 15px；阅读栏正文 15px、行高 1.75。
- “显示”菜单中的“紧凑行”把英文名和版本标签移到中文名同一行、名称列加宽到 340px 并收窄行距，适合快速扫读长列表；与核对模式一样，它是本浏览器的阅读偏好，保存在 `localStorage`（`anna.density`），同源标签页同步，不写入查询 URL。
- 银灰承担工作台外壳：`canvas` 承载顶栏，`surface` 承载查询区域，`paper` 承载结果和阅读内容。边框划分区域，阴影只用于窄屏浮层。
- 酒红（`brand`）只表达 anna 加在原文上的东西：所选类型与当前条目、已选筛选、提取字段及其证据。`focus` 单独表达键盘焦点；`warning`、`success` 表达已有的数据状态。颜色不替代文字、符号或可访问状态。
- 多选项保留方形选中标记；互斥条件使用分段按钮。未选的取值保持中性色，选中的取值使用强调色。
- 已选条件一行横向滚动：不显示滚动条（滑块停在第一项下方时像是选中标记），只在还有更多条件的一侧淡出边缘（`.fade-strip`）。
- 结果保留表格与各类型的列顺序。表头和名称列固定；英文名、来源、规则版本保持可读，属性通过横向滚动查看。列不会被压窄到内容以下：名称列（`--anna-name-column`，248px）和长文本列（220px）宽度固定、在列内换行，其余列按内容取宽，结果区变窄时整表横向滚动，因此行高与结果区宽度无关。法术的言语、姿势、材料合并为“成分”列，仪式与专注合并为“仪式/专注”列，以字形条显示：具备的成分为实色，不具备的变淡，未提取与冲突分别标出，特殊材料附 `*`。读屏读出完整名称与状态；筛选和 CSV 导出仍逐项保留五个布尔字段（schema 的 `composites` 与 `export_columns`）。
- 名称排序按自然顺序：数字按数值比较（“2级”在“10级”之前），忽略大小写与全角半角。全部条目等混合多种类型的结果默认按类型的阅读顺序排列（`browse.TYPE_ORDER`：职业、子职、职业能力、种族、背景、专长、法术、装备、魔法物品、生物，再到规则与资料），同类再按名称；首屏因此从职业开始，而不是价格表里以数量开头的货物行。职业能力的等级是单独的字段，不在名称里：职业能力有“等级”列和筛选，默认按等级排序。
- 搜索框按名称包含关系筛选；没有自选排序时，结果按匹配程度排列：中文名或英文名与搜索词完全相同在前，以搜索词开头次之，仅包含在后，同档内名称短者在前，再按该表的默认排序（`browse.sort_key`、`browse.match_rank`）。搜“火球”时，火球术因此排在延迟爆裂火球之前。排序菜单在搜索时多出“匹配度”一项；读者自选的排序写入 URL，搜索期间保持有效。URL 只记录自选的排序，未自选时由服务端与页面按同一规则推定。
- 屏幕宽度不超过 640px 时，结果改为列表：名称独占一行，其余属性以“列名 值”依次排列，不再横向滚动；排序使用结果栏的排序选择。列表与表格的切换只看屏幕宽度，不看结果区宽度，打开阅读栏因此不会把表格改排为列表。
- 宽屏下，表格上方的标题、条件栏和结果栏都只占一行：放不下的计数和说明截断（计数悬停显示全文），条件标签在条件栏内横向滚动；760px 及以下条件栏独占一行，输入在上、标签在下；“合并同名版本”“优先显示”“紧凑行”收在结果栏的“显示”菜单里，链接带有非默认的版本显示方式时菜单按钮带一个圆点；导出 CSV 位于结果底栏右端。结果区变窄时这些行只隐去次要文字（排序标签、图例），高度不变。
- 筛选区默认收起，首屏留给结果；已选条件始终显示在条件栏中，可逐项移除。展开后，所选类型的前两组多选和 CR 范围优先显示，其余领域条件放在“更多筛选条件”中，带相应参数的直接链接自动展开该部分。
- 控件使用短时颜色反馈；遵循 `prefers-reduced-motion`。不引入聊天气泡、装饰性加载光效、专有字体或网络字体。

## 同一取值，同一读法

同一字段若在表格写作“牧 法 契”、在阅读栏写作“牧 法 锁”，读者无从判断两者是否一回事。原文的写法因书而异（魔契师写作“锁”或“契”，材料写作 `×`），anna 归一化后的取值才是比较、筛选和差异判断的依据。因此表格、阅读栏的“属性”、字段批注和“版本对照”都经由同一个格式化函数（`fieldText`）显示归一化后的值；原文写法保留在“证据”栏目。

- 表格取短形式：职业缩为单字，悬停显示全称；阅读栏写出全称（“牧师、法师、魔契师”）。两处来自同一组归一化取值，只是密度不同。
- 是否类列（传奇动作、同调）以 `✓` 表示是，淡色圆点表示否，`—` 仍只表示未提取，`⚠` 表示冲突；读屏读出“是 / 否”。阅读栏用文字“是 / 否”。
- 规则版本显示为规则代际：表格徽标与版本标签写作 `2014` / `2024`，悬停和阅读栏写作“2014 版规则（5e）”。它表示规则代际，不是出版年份。
- 来源显示构建时确定的短标签，悬停显示全名（`source_extract.source_labels`，各来源唯一）：分册有自己的缩写时用缩写；只有系列缩写（UA、Drops）时写作“系列缩写 + 分册名”，如“UA 灵能I”，分册名已含该缩写（“新UA”）时不再重复。名录未给缩写的冒险模组和电子资源不自造缩写，而是缩短书名：形如“主标题：副标题”的书名取能单独指认该书的部分，主标题优先（“冰风谷”），两本书共用主标题时改用副标题（“龙金之劫”“疯法师地城”）；卷号、期号和纯拉丁字母的系列标记（“卷四”“CR”）不单独作标签。阅读栏写出全名并附缩写，便于与表格对应。
- 阅读栏“属性”按条目类型的表格列排列（`browse.field_order`），其余规则字段按提取顺序跟在后面，`X_detail` 紧随 `X`；类型、来源、来源缩写、规则版本、旧版标记这些标识版本本身的字段（`browse.METADATA_FIELDS`）排在最后。同一组字段也不参与版本比较，也不作为字段批注。

## 同名版本并排

同一法术、生物或物品常在多个版次和规则代际中各有一条记录。逐行罗列会让同名条目相邻重复，版本之间的规则差异要隔行对照才能发现。默认结果因此把同名候选组（`identity_candidates`）中的版本合为一行，回答“这件东西有哪些版本、它们有何不同”。

- 名称下列出各版本标签（来源缩写与规则代际，如“PHB24 2024”），待核版本用虚线；点击标签打开对应条目，所在行保持选中。行内数值来自优先规则版本：默认 2024 版规则（5r）优先，其次 2014 版规则（5e），最后待核；同一规则版本中取当前排序靠前者。“显示”菜单的“优先显示”可改为 2014 优先。
- 某一列的取值在版本间不同时，显示值加点状下划线，其他版本的值列在下方。比较前统一空白与全角半角；未提取、冲突或不适用的值不算差异。名称、来源、版本、类型、分类依据与旧版标记标识版本本身，不参与比较。
- 合并只在当前筛选结果内进行：筛选决定哪些版本存在，每组出现在其优先版本的排序位置。计数同时给出行数与版本数，分批加载按行进行。
- 只有英文名能标识同一出版对象的类型才并排：法术、物品、生物、专长、种族、背景、职业、子职、载具、状态等（`browse.STACKABLE_TYPES`）。职业能力按职业限定作用域，规则与资料段落常共用通用标题，同名时仍各占一行。
- 取消“合并同名版本”回到一个版本一行（`versions=each`）；5e 优先记为 `prefer=5e`。两者写入 URL 与历史，切换时阅读栏保持打开。CSV 导出始终一个版本一行。
- 阅读栏标题下列出同组全部版本，不受当前筛选限制；“版本对照”栏目逐字段比较，不同字段在前，相同或未提取的字段折叠。在版本间切换时保留当前栏目。同组关系是候选，不代表同一规则身份。

## 阅读模式与核对模式

默认的阅读模式服务于查阅规则：分类依据与旧版标记的筛选、“分类依据”“旧版标记”列、引用审核工作台入口，以及阅读栏中的证据、概念线索、有效引用和待核栏目都收起。阅读栏底部保留一行核对摘要，列出这些栏目的数量；点击摘要即开启核对模式并打开证据栏目。条目被明确标旧时，阅读栏仍显示旧版标记；字段冲突在两种模式下都显示。

核对模式下，阅读栏先列阅读栏目（正文、属性、版本对照、关系），再在“核对”分组名之后列证据、概念线索、有效引用和待核；数量为 0 的栏目淡化，仍可打开。

顶栏的“核对”开关切换两种模式。选择保存在当前站点的 `localStorage`（`anna.audit`），同源标签页同步，不写入查询 URL；存储被禁止时仍可在当前页切换。共享链接中已带的审核筛选（分类依据、旧版标记、仅字段冲突、包含未分类段落）在阅读模式下照常生效，筛选区继续显示对应分组，便于核对和移除。关闭核对模式时，若阅读栏停在审核栏目，则回到正文，不关闭条目。

## 品牌头像与网站图标

查询页使用银白短发、酒红龙角的 Anna；不全书阅读器使用紫色低发髻、蓝眼睛和蓝色星图龙角的 Stella。主图与生成提示词保存在 `assets/branding/`。运行 `uv run scripts/build_icons.py` 重建两者的顶栏 PNG（128px）、多尺寸 ICO（16–256px）和查询页单尺寸 favicon PNG（16、32、48px）；加 `--brand stella` 可仅导出阅读器素材。`output/imagegen/` 下的 `anna-favicon-preview.png` 和 `stella-favicon-preview.png` 提供浅／深底原尺寸与像素放大对照。Pillow 仅用于离线导出，运行服务无需安装。

查询页声明各尺寸 PNG 和 `/favicon.ico`，审核页与页面文本视图共用该 ICO；阅读器声明 `/stella-favicon.ico`。服务仅开放明确的静态路径，不开放素材目录。

查询页和阅读器都以 36px 正方形显示透明头像。固定宽高避免加载时位移，并保持原图比例与完整龙角。头像与应用名共同构成首页链接，图片使用空替代文本，避免读屏重复播报；窄屏保持头像尺寸与名称，不挤压变形。

## 浅色、深色与系统外观

右上角采用与不全书相近的图标按钮：单击按“浅色 → 深色 → 跟随系统 → 浅色”循环，太阳、月亮和显示器分别表示这三种偏好。默认跟随系统；循环顺序由当前偏好决定，不随系统实际配色改变。键盘聚焦按钮后，Enter 或空格执行相同的循环，悬停提示说明当前状态与下一次点击的目标。页数、版本及“本地只读”状态信息不再占据顶部空间。

明确选择保存在当前站点的 `localStorage`（`anna.theme`）；恢复跟随系统会移除此值。主题不写入查询 URL 或历史快照，切换时保留筛选、阅读位置与打开的条目。同源标签页同步选择，系统外观变化仅影响跟随系统的页面；浏览器禁止存储时仍可在当前页切换。

`theme.js` 在样式表之前执行，首屏即应用保存的选择，并独立提供中英文主题控件文案；查询 API 失败不影响外观切换。`style.css` 以 `data-theme` 覆盖语义颜色，同时设置原生控件的 `color-scheme`；错误、警告、成功、高亮与遮罩各自使用配套前景／背景色。深色沿用暖灰表面和提亮的酒红强调色，不反相头像或页面。

anna 的页面文本视图共用主题设置。链接版不全书保持原文呈现，不跟随 anna 改写书籍样式。

## 原文排版与字段批注

提取文本保留了文字，却丢掉了表格、标题和强调：数据卡的属性表会压成一串“调整豁免调整豁免”。阅读栏的“正文”因此显示条目所在原文页面的排版，并把 anna 读出的字段作为批注，标在它们所依据的文字上。

- `scripts/entry_layout.py` 读取原文镜像中的页面，确认文件哈希和解析文本都与数据库快照一致，再按条目的文本范围序列化相交的 DOM。来源标签映射到一小组无行为的元素（段落、标题、强调、列表、表格等），只保留表格的 `colspan`／`rowspan`；脚本、图像、链接地址、内联样式与原有类名一律不复制。不超过 12 个字的表格单元格保持整行，长单元格按正文换行。条目标题行已由阅读栏标题显示，排版和提取文本都从标题之后开始（`entry_layout.text_start`）。
- 原文常把整条法术写在一个段落里，靠 `<br>` 分行，段与段之间没有间距。块元素自身的换行因此拆成独立段落。以粗体开头、粗体以冒号结尾、冒号前有 2 至 12 个字的行是“标签：值”；连续两行以上的这种行组成参数卡（`dl.parameters`），按两列排列，标签不再重复冒号，值超过 24 个字时占满整行。规则只看原文结构，不列举字段名：法术的施法时间与距离、背景的属性值与装备、职业的生命值骰与熟练项、种族的类型与速度都由此成卡；单行标签、`Q：`／`A：` 这类单字问答保持段落。
- 字段证据（`facts`）与已解析的有效引用使用提取时的同一套规范文本偏移：证据范围包上 `mark.note`，引用变为打开目标条目的按钮。原文明示的证据用实线下划线，上下文推得的用虚线。证据跨元素时在每一侧分别标记。
- 批注按首个证据在正文中的位置排列；证据来自速查表等其他页面的字段排在最后，标为“证据不在本段原文”。悬停或聚焦批注时，对应文字高亮，反之亦然；点击批注将文字滚入视野。阅读栏内容宽度达到 680px（正文仍保有约 32 字一行）时批注排在页边，更窄时列在正文之后；没有批注的条目不保留页边。类型、规则版本、来源等标识版本本身的字段不作批注。
- 段落、列表与参数卡限宽 40em（正文字号下约 40 字一行），表格不受此限。每张原文表格包在自己的横向滚动框（`.table-frame`）里，宽表格只在框内滚动，不带着正文横移；表格宽于阅读栏时，框上方出现“表格宽于阅读栏 · 全宽阅读”，点击即进入全宽阅读。
- `/api/entry-layout` 在原文缺失、已更新或范围为空时返回相应状态。打开条目时它与 `/api/entry` 同时请求，阅读栏等待排版至多 400ms（`LAYOUT_WAIT`），通常直接显示排版；更慢时先显示提取文本，排版到达后替换。无法排版时保留提取文本并说明原因，不显示局部结果。链接版保留原文正文与排版，此处的条目排版是派生视图，不回写原文。

## 分批加载

结果列表不分页，而是随滚动分批加载：浏览一长串按环阶排好的法术时不必停下来点击翻页，结果栏也省下了每页数量与页码控件。

- `/api/entries` 以 `offset` 与 `limit` 读取一段结果，每批 150 行；一次最多 1,500 行，供恢复历史位置使用。合并同名版本时按行计数。
- 滚动到距列表末尾 600px 内时自动加载下一批。底部同时保留“继续加载”按钮，供键盘和读屏使用；在最后一个名称上按下方向键，也会加载下一批并把焦点移入。底栏以状态区播报“已显示 300 / 933 行”，全部加载后改为“已全部显示”。
- 自动加载、按钮、方向键和阅读栏箭头共用同一个进行中的请求，不会重复读取同一批。追加的行不使已有结果变淡；追加失败时保留已加载的行，底部显示错误，按钮变为“重新加载”，并暂停自动加载直到再次点击。
- 阅读栏的“下一条”跨过已加载的末尾时先加载下一批，再打开下一行；位置显示为“第 151 / 933 行”。打开的条目若不在已加载的行中，提示“不在已加载的结果中”。
- 加载位置不进入 URL。已加载行数与列表滚动位置记在 `history.state.anna`，刷新和前进后退时一次读回相同行数并恢复位置。旧链接中的 `page`、`size` 参数在载入时移除，其余查询条件保留。
- 不做只渲染可见行的虚拟滚动，固定表头、固定名称列与焦点行为保持简单。最长的“全部条目”全部加载后仍可流畅滚动，实测见[查询界面验证](../tests/query-ui-validation.md)。

## 阅读空间

查找时，空间属于结果表；阅读时，条目需要适合阅读的行长与表格宽度。两者共存的前提是：读者点击的东西留在原处。更早的版本打开条目时把分类目录收为按钮、把结果改排为列表，被点击的行从 y=587 跳到 y=854，目录、工具栏和每一行都换了位置，连续查阅时读者每次都要重新找回刚才的位置。打开条目因此只在结果右侧加入阅读栏，其余一切留在原处，实测对比见[查询界面验证](../tests/query-ui-validation.md#2026-11-08-位置稳定验证)。

- 宽屏打开、切换和关闭条目时，标题、搜索栏和结果的每一行都停在原处，阅读栏只从结果区取走宽度。这由布局本身保证：结果始终是表格，行高不随宽度变化，表格上方各行在任何宽度下都只占一行（见“视觉规则”）。`detail.js` 的 `holdResultRow` 在阅读栏开合前后测量正在阅读的行，若仍有位移（例如展开的筛选区变窄后重新排版），就滚动结果列表抵消。
- 结果的整行都是点击目标：单击行内任意位置打开该行显示的版本，版本标签打开对应版本；拖选行内文字不打开条目，取值仍可复制。名称按钮仍是键盘与读屏的入口。触屏设备上版本标签加高到 30px。
- 双击结果以全宽阅读打开。第一下单击已经打开条目，第二下落在原处未动的同一行上，只表示“全宽阅读”：不重复打开条目、不触发其下的控件、不选中文字；760px 及以下阅读层本已铺满，双击等同单击。
- 阅读栏默认占工作区宽度的 60%。阅读栏左缘是可拖动的分隔条（`role="separator"`）：左右方向键每次调整 2%，Shift 加大到 10%，Home、End 到达边界，双击恢复默认。阅读栏至少 400px，结果至少 360px（`--anna-reader-min`、`--anna-list-min`），CSS 网格轨道与 `detail.js` 使用同一组边界。
- 上一条、下一条在阅读栏内原地替换条目：当前条目保留到下一条就绪，超过 180ms 未就绪才变淡，不闪出“正在读取”；结果列表随之滚动，使当前行留在固定表头之下的可见范围内。阅读栏打开时以 160ms 淡入，遵循 `prefers-reduced-motion`；首次打开的读取提示在 250ms 后才出现。
- 全宽阅读把阅读栏铺满工作区，内容居中排为至多 1120px 的一栏；正文栏按内容取宽（正文行长或最宽的表格），页边批注紧随其后。结果保持布局与滚动位置，只是暂不可见。双击结果、工具栏按钮或宽表格上方的提示进入全宽阅读；宽屏按 F6 回到结果时先退出全宽阅读。1200px 以下，全宽阅读把模态阅读层扩展到整个窗口；760px 及以下阅读层本已铺满，不提供该按钮。
- 阅读栏宽度（`anna.readerShare`，默认值不存储）和紧凑行一样，是本浏览器的阅读偏好，保存在 `localStorage`，同源标签页同步，不写入查询 URL。全宽阅读属于一次阅读：上一条、下一条与条目内链接保持全宽，关闭阅读栏即结束；它记在 `history.state.anna`，刷新和前进后退时恢复。若它也是长期偏好，双击一次之后每次单击都会以全宽打开，单击与双击就失去区别。
- 条目头部收为三行：中英文名同行，其次是类型、规则版本与来源，再是版本标签和两处外链；仅有内容时才显示徽标行。栏目条在滚动时固定在阅读栏顶端；头部滚出视野后，工具栏以条目名代替“条目阅读”。键盘提示写在正文末尾，不再占用固定底栏。
- 1200px 以下的模态阅读层宽至多 920px，足以并排正文与页边批注。

## 阅读与状态

`detail.js` 管理同一个原生 `dialog`：CSS 视口宽度达到 1200px 时使用 `show()` 作为工作区的非模态第二栏，更窄时使用 `showModal()` 作为阅读层。两端切换保留内容、滚动位置和阅读层内的焦点。CSS 和 JavaScript 的 1200px 断点需同步修改，边界由浏览器测试约束。

结果列表可连续打开不同记录。筛选或类型变化会关闭旧详情；加载更多结果、切换合并或优先显示时保留正在阅读的条目。

URL 保存查询、筛选、排序、版本显示方式和条目身份。`history.state.anna` 保存本标签页的面板展开、已加载行数、列表及详情滚动、详情栏目和返回焦点目标；不把这些临时偏好写进共享 URL。刷新和历史导航在数据加载后恢复位置。新查询回到列表顶部；打开和关闭详情不移动正在阅读的行，从阅读栏逐条查阅时列表只滚动到让当前行可见。

查询等待期间，结果区保留上一次完成的表头、行和计数，整体变淡且不可操作，继续加载与导出暂时禁用。新响应到达后，表头、首批行和计数一次替换，分类切换时不会先清空表格或混排新旧列。查询失败则清空行和计数，只保留错误提示与恢复入口。

每次条目请求有递增序号；旧请求迟到或关闭后返回时，不覆盖当前阅读内容。逐条查阅期间保留的上一条目不可点击，直到新条目替换它。读取失败保留关闭与重试入口，不把失败显示为空正文。

## 品牌、标题与两位向导

条目查询以 5e Anna 为品牌，不全书阅读器以 5e Stella 为品牌；两个名称各自标明所在页面的向导，不翻译，也不再附加“条目速查”“不全书阅读”之类的页面名。动态界面文案与网页标题使用 `link-labels.js` 中的 `annaBrands`。

网页标题统一为“内容 · 品牌”，由 `annaPageTitle` 生成：anna 在打开条目时显示条目名，否则显示当前类型预设（“全部条目”只显示品牌）；stella 显示当前页面标题。各自的品牌链接回到本页首页。

两页是同一工作区里的两位向导：Anna 回答查询，Stella 陪读原文。读者在两页之间往返时，常常想带着正在看的条目过去，或回到上次和对方停下的地方；早先顶栏只有一个品牌名链接，看不出它会去哪里，往返一次还会丢掉查询条件。现在两页共用页面模块、顶栏组件和一份共享状态，切换时看得见去向，回来时回到原处。

### 顶栏

两页顶栏由 `topbar.js` 绘制：页面的 `header` 写明 `data-page` 并只放本页专属控件，脚本紧跟其后运行，在首次绘制前补全头像、品牌名、另一位向导和主题按钮。右侧依次为本页专属控件（查询页的“核对”开关）、另一位向导和主题按钮；另一位向导在两页的同一位置，切换页面时不移动。阅读器专属的控件都放在正文上方的阅读栏，见[正文呈现与切页](#正文呈现与切页)。

另一位向导由 `companions.js` 绘制：她的头像加一句去向，例如“翻到 火球术”“接着读 三环”“回到 法术 · 火球”。去向按以下顺序选择（`annaWorkspace.offer`）：

1. **话题**：另一位向导展示过、而你此后还没来找过她的条目。
2. **最近打开的位置**。
3. **她的首页**：没有可接的话题，也没有最近打开的位置。

标签总写出去向；640px 及以下只留头像，去向保留在无障碍名称与悬停提示中。还有其他选择时，旁边出现“▾”，菜单分组列出“当前”的话题和“最近”的位置，每项带另一位向导的头像。菜单与 Stella 位置路径的菜单共用 `menu.js`：↑↓、Home／End 移动，首字跳转，Esc 关闭并回到按钮，Tab 离开即关闭。顶栏切换在当前标签页打开，浏览器后退回到原处。

条目处的入口保留各自职责：Anna 阅读栏的“在 Stella 中阅读”（带 Stella 头像），以及 Stella 正文的定义标题和“本页”列表中的箭头，在新标签页打开另一位向导以便对照；它们打开的条目同样成为话题。阅读器正文区域不增加条目入口，保持原貌阅读。

### 共享工作区

`workspace.js` 维护两页共享的一条记录，保存在当前站点的 `localStorage`（`anna.workspace`），并以构建快照（`/api/meta` 与 `/api/reader` 的 `snapshot`）绑定：

| 内容 | 何时更新 | 数量 |
| --- | --- | --- |
| 话题 `topic` | Anna 打开条目、Stella 经条目进入或读到某个定义时；展示它的一方关闭该条目即结束 | 1 |
| Anna 的位置 `query` | 每次保存查询状态。以查询条件区分，不含打开的条目与未完成的输入；只改条件时替换最新一条，打开过条目的查询才留下 | 5 |
| Stella 的位置 `book` | 每次保存阅读位置。以阅读范围区分，范围内移动只更新这一条；目录之外的页面各成一个范围 | 5 |

同一条目再次展示时，话题保留原来的来源与时间，所以沿话题过去再回来，不会被当成新话题；恢复最近打开的位置或历史记录时重新显示的条目也不算新话题。构建快照变化后只保留查询条件，条目、恢复视图、阅读位置和话题都丢弃。同源标签页通过 `storage` 事件同步；存储被禁止时，两页照常工作，另一位向导只指向首页。

从按钮或菜单选中一个最近的位置时，`requestResume` 在本标签页的 `sessionStorage` 留下一次性请求，目标页载入时取走：Anna 恢复该查询已加载的行数、滚动和阅读栏，打开的条目已不同时只恢复列表；Stella 恢复该范围内的页内位置。修饰键或中键打开的新标签页不带请求，从头载入。前进后退仍由各标签页的 `history.state` 负责。

直接运行 `scripts/serve.py` 时 `/api/meta` 没有阅读器和快照，查询页不显示另一位向导，也不写共享工作区。

## 整页阅读器

条目详情用于核对一个记录，整页阅读需要保留章节与相邻内容。`/read` 因此使用独立布局，共享查询页的设计变量、主题、条目身份和有效引用结果；界面由原生 JavaScript 实现，不引入框架、额外打包步骤或热加载服务。修改应用文件后刷新即可，正文增强脚本属于构建产物，修改后运行 `make linked` 并重启 `make up`。

### 内容与导航边界

`scripts/reader.py` 将现有 `inventory.Toc` 的结果归一化为目录节点，保留节点 ID、父子顺序、页面、原锚点和缺失状态。目录节点不等同于页面，也不等同于条目；重复页面保留多个入口，不在前端根据名称重建身份或书籍归属。没有目录的输入只列页面，不推断书籍层级。

`scripts/linked_book.py` 从同一数据库与原文快照生成 `anna-reader.json`：目录供初次加载使用，页面保存标题与按正文范围排序的条目列表。原文已纳入哈希快照、但未参与提取的编辑说明和模板页也进入阅读数据；这些页面没有条目范围，不强行补出定义。生成器不复制根目录的 HTML 阅读壳，保留正文与其资源，在所有正文页追加 `book/topic.js`。构建把旧壳脚本加载标签及完整匹配的 WinCHM 目录同步脚本替换为惰性注释，不重序列化 HTML；注释保持节点位置，正文文字、编码、锚点和范围绑定不变。产物只包含 `topics/` 正文资源及明确列出的四项呈现资源，不复制旧导航、搜索、书签、预绘制脚本和外壳图标。

应用由 `scripts/up.py` 在单一端口提供：查询与 `/read` 使用应用路由，`/book/` 只开放清单中的正文资源及定位路由，没有另一套首页、目录页面或搜索页面。`create_server` 创建一个 HTTP 服务，脚本以 `--port` 指定端口。应用 CSP 仅在 `/read` 允许同源 iframe；正文在独立文档中隔离样式，但与应用同源，不再作为脚本安全隔离边界。原文脚本来自显式获取并校验的本地快照，不用于承载任意外部 HTML。直接运行 `scripts/serve.py` 时不显示阅读入口，完整查询与阅读使用 `make up`。

### 只读接口与通信

| 接口 | 返回内容 |
| --- | --- |
| `/api/meta` 的 `reader_url` | 完整服务提供 `/read`；单独查询服务为 `null` |
| `/api/reader` | 构建快照、目录节点、默认页面、不全书发行版本 `source_release`、正文资源前缀 `content_base` |
| `/api/reader-page?path=…` 或 `?entry=…` | 页面标题、正文路径、可定位状态与本页条目；条目请求另含定义锚点 |
| `/api/book-search?keyword=…` | 本机全文结果；沿用 `book_search.search_entries`，附带全部词／任一词命中状态 |

页面与条目参数互斥，重复参数、缺失目标、无法定位及快照不符分别返回明确状态；浏览器不把错误当成空正文。阅读 API 可携带 `snapshot` 拒绝跨快照请求。完整数据库、目录与正文产物由启动校验绑定，运行中重建会使旧进程返回 409；启动期间原文发生变化也不能混用新搜索索引和旧阅读数据。

`book/topic.js` 负责原文与应用之间的高度、定位、导航、主题、链接标记和焦点通信。双方检查消息版本、origin、source、快照、文档 ID 和导航序号；正文的构建快照与呈现资源随绑定数据嵌入；双方使用当前同源地址发送消息，不使用 `*`。引用目标仍由现有 `book/links.js` 与有效引用模型决定。正常点击的内部链接交由阅读壳处理，带修饰键或中键的内部链接打开新的阅读器；原文外部链接与条目新标签页入口保持原有职责。

侧栏显示不全书自身的发行版本，而非构建哈希。`source_release` 从当前只读镜像的 `topics/写在前面.html` 中「DND 五版不全书 v…」标题提取，保留版本值与证据页面路径；日期无效、声明缺失或多个版本冲突时返回 `null`，界面不显示版本。它与规则代际、各书版次及内部 `snapshot` 分开：`snapshot` 仍用于发布一致性和阅读位置校验。侧栏快捷键提示仅显示「/ 搜索」，其余键盘操作见[使用说明](../USAGE.md#阅读操作)。

### 导航与状态

`web/reader-model.js` 从有序目录建立阅读范围：以 `root` 指定的目录节点作前序遍历，仅加入自身及后代的可用正文。分组和缺页节点仍遍历其子节点；相同路径只挂载一次，保留各目录入口及锚点。叶子范围不包含兄弟节点，未编入目录的页面使用单文档范围。显式范围不存在、范围为空或目标不属于范围时报告错误，不扩大范围或替换目标。

`web/reader.js` 管理应用导航与历史。URL 的 `root` 固定阅读范围，`entry` 或 `page` 指定当前位置，`anchor` 保存原锚点，`node` 保存当前目录入口。目录和位置路径中范围外的祖先建立新范围；分页、位置路径的范围内层级、本页条目与范围内正文引用保留范围，范围外引用建立新的范围。滚动切换当前文档只替换 URL 和历史状态，显式导航才新增一条历史记录。

`web/reader-flow.js` 管理按范围顺序排列的文档槽位。首次挂载目标页，正文末端进入视口下方的预加载区时顺序接续下一页；预加载区为一个视口高度，上限 600px。同一时刻只运行一个自动请求，页面在后台时不启动新的自动请求；失败保留原位重试按钮，不因滚动或重排反复重试。手动接续与分页跳转复用同一文档槽位，正在载入的正文不会重复挂载。远距离跳转不逐页读取中间文档，中间未加载部分合并为带接续按钮的区间。分页选项与计数始终来自完整范围，与已挂载数量无关。

活动正文以视口所在页面为中心，自动加载只在前后各两页的窗口内运行，最多挂载 5 个 iframe（包括正在加载的文档）。前台跳转优先为目标留出容量；当前成功显示的页面在新目标就绪前保留。窗口之外的文档释放 iframe、绑定数据和未完成请求，用等高占位保留滚动空间。接近已回收页面时优先重新加载，支持向前和向后滚动，也提供手动重新载入按钮；当前位置之前、尚未加载的区间仍由读者主动接续。短页填满局部窗口后停止自动接续，避免静止视口一路加载整本书。

占位高度来自上次实际测量，不保留原文 DOM；窗口尺寸变化后的旧高度仅用于暂占空间，重新加载后由正文测量值替换。补页、回收和高度校正以视口文档及其局部偏移补偿滚动，未回收的 iframe 保留原节点，不移入临时 fragment 重建。停留在尚未重新就绪的占位时，不覆盖最后成功阅读位置；释放持有焦点的远页时，焦点转到外层阅读滚动区。

正文 iframe 只隔离样式，高度由 `book/topic.js` 测量正文并通过版本 2 协议上报，滚动由 `#book-scroll` 统一承担。`initialized` 与 `size` 消息另附本页各定义起点的文档内纵坐标；起点越过视口顶端下方 48px 的最后一个定义即正在读的定义，成为共享工作区的话题。缺少该字段的旧正文产物只是不跟随话题。定义定位复用 `book/links.js` 保存的文本节点范围，bridge 返回文档内坐标，外层结合文档位置滚动；原文锚点也遵循同一路径。每个文档校验来源窗口、origin、快照、文档 ID 与初始化序号；每次定位另有请求序号，离开范围会取消待处理请求，旧响应不能覆盖新范围。已读文档之前的高度变化或区间插入，以当前文档内位置补偿外层滚动。

`history.state.book` 与[共享工作区](#共享工作区)中 Stella 的位置保存快照、阅读根、当前文档、目录入口和文档内坐标，不依赖所有前页的累计高度。历史另保存目录展开、导航栏目和搜索状态。恢复先加载当前文档，其余区间可手动补入；不同快照、无效坐标或不属于指定范围的记录不用于恢复。只有没有显式定位参数且没有可用历史状态的入口才采用最近阅读记录，加载失败不覆盖最后成功位置。早期版本把单个位置存在 `anna.bookPosition`：首次载入时按同样的规则校验它（版本 1 的单页记录按原目录入口归一化），在工作区还没有 Stella 位置时导入为第一个位置，随后删除该键。这一导入只为保留升级前的阅读位置；不再需要迁移旧浏览器数据时，可删除 `importLegacyPosition` 与版本 1 归一化。主题复用 `anna.theme`，存储被禁用时仍可阅读与导航。

目录只渲染展开的分支，过滤期间使用匹配节点及其祖先，不修改展开集合。目录入口使用 roving tabindex 和方向键；导航的三个栏目使用 tablist。800px 及以下，同一个导航 `dialog` 改用 `showModal()`，形成有焦点约束的抽屉；窗口跨过断点时保持正文文档，不重新加载页面。新文档加载期间显示该槽位的加载状态，已有文档保持可读。

目录跟随与阅读范围独立。滚动跨页后以当前范围中的目录入口更新高亮，等待 180ms 内没有新的页面切换再同步目录；同页滚动不重新定位。开启跟随且目录可见时，仅展开必要的祖先，并按当前行超出目录视口的距离调整 `#book-tree-scroll`，不调用会连带滚动正文的 `scrollIntoView`。关闭侧栏或查看其他导航栏目时只更新当前项，重新打开目录后再定位，不自动展开抽屉或切换栏目。

筛选、展开／收起、目录方向键、滚轮、触摸滚动及滚动条拖动会暂停跟随。点击“定位当前章节”清空筛选并恢复跟随。

目录工具收在栏目下方的一行图标里，以图标的 `aria-label` 与悬停提示说明用途：

- 筛选：默认只显示放大镜（`#book-filter-open`），点击后在原位展开筛选框；筛选框展开期间隐藏“展开当前章节”和“全部收起”，旁边只留“定位当前章节”。框中有文字时保持展开，刷新与历史恢复也随文字展开；为空时失焦或按 Esc 收回并把焦点还给放大镜。Esc 逐层后退：先清空文字，再收回筛选框，窄屏最后关闭抽屉。
- 定位当前章节：跟随状态写入只供读屏播报的 `#book-follow-status`；视觉上由该图标承担：跟随时显示为品牌色，暂停时恢复普通图标色，提示文字改为“定位当前章节并恢复目录跟随”。
- 展开当前章节：展开阅读范围根节点的祖先与全部后代，并把范围根节点滚到目录顶部；不改变跟随状态。阅读范围不在目录中时不可用。
- 全部收起：清空全部展开状态，并暂停跟随。普通滚动事件仅保存位置，不用于推断用户意图，避免程序定位或历史恢复触发误暂停。暂停时跨页只原位更新高亮，不重建目录 DOM，保留浏览位置和键盘焦点；自动展开需要重建时也保留原焦点。`history.state.book.followContents` 与目录展开、筛选和滚动位置一同恢复，旧记录未指定时默认开启；新的阅读会话默认开启，不写入跨会话阅读位置记录。

### 正文呈现与切页

顶栏与查询页同高，保持一行。其下的阅读栏（`#book-bar`）与正文同宽，从左到右依次为：

- 目录侧栏开关：与主题按钮同为无边框图标按钮（`.icon-button`），展开时以品牌色标示。加载失败时错误提示只覆盖正文，开关仍可用，便于从目录重新查找。宽屏侧栏紧邻此开关，因此不另设关闭按钮；窄屏抽屉为模态并遮住阅读栏，标题行右端保留关闭按钮，也可点背景或按 Esc 关闭。
- 位置路径（`#book-path`）：从阅读范围的祖先经范围名称一直写到当前页，以范围名称（`#book-scope-title`，加粗）为界分成两段。范围外的祖先是浅色链接，点击即以该节点建立新范围；范围名称链接到范围第一页。范围名称之后的每一层都是按钮，点开列出该层在目录中的同级节点；当前节点还有下级时，末尾的“›”列出它的子节点。路径因此兼作一次展开一层的目录：读者沿树上下移动，不必打开侧栏。未编入目录的页面以“未编入目录的页面”代替祖先，没有可展开的层级。
- 分页器：上一页、当前页／总页数与下一页合为一个分段控件，按目录顺序逐页移动；箭头的提示写出前后页名。
- 链接标记（`#book-link-marks`）：阅读栏末端的开关，与顶栏末端的主题按钮一样调整正文的呈现。图标是一行文字中的一段高亮，开启时以品牌色和选中底标示（`aria-pressed`）；悬停提示与无障碍描述写出颜色的含义。

路径菜单里的选择与分页一样只在范围内移动：替换当前位置并新增一条历史记录，不重建范围。只是分组的节点打开它的第一个可读后代，没有可读后代的节点列出但灰显、不可选；菜单项后的数字是该节点的下级数量，只供视觉参考。同一时刻只有一个菜单（`#book-path-menu`，`role="menu"`），菜单项是带地址的链接，可以中键或用修饰键在新标签页打开。

键盘上，路径按钮按 ↓ 打开菜单并聚焦当前所在项，↑ 聚焦末项；菜单内 ↑↓ 循环移动，Home、End 到达两端，输入首字跳到下一个以它开头的项，← → 换到相邻层级的菜单，Enter 或空格打开，Esc 关闭并回到按钮，Tab 离开时关闭。选中后焦点回到路径中同一位置的按钮。没有可选项时焦点停在菜单本身。

路径宽度不够时按固定顺序收起：先收范围外的祖先（800px 及以下始终不显示），再从外向内收起范围内的中间层级，最后收起范围名称；当前层级始终保留，仍不够时截断并在悬停时显示全名。收起的范围内层级合成“…”按钮，菜单按层级缩进列出它们。收起由 `ResizeObserver` 在阅读栏宽度变化时重新计算：测量时暂时禁止当前层级收缩，确保先收起其他层级再截断当前页名。

侧栏标题行与阅读栏同高并共用底线；“目录／本页／搜索”等宽平铺，当前栏目以浅色选中底和品牌色文字标示，悬停只加深文字。

原文没有为 anna 加上的链接留下记号，读者原先只能把光标移到文字上，看指针是否变化。链接标记让这些链接直接可见：开启后，点击层已绑定的每个范围都铺上淡色文字底色，颜色写出点击后的去向。

| 范围 | 底色 | 点击后 |
| --- | --- | --- |
| 正文引用 | Stella 的蓝 | 在阅读器内跳到定义 |
| 定义标题 | Anna 的酒红 | 在新标签页打开 Anna 条目 |

- 标记由 `book/links.js` 绘制为两组 CSS 自定义高亮（`anna-reference`、`anna-definition`），颜色在正文文档采用的样式表（`adoptedStyleSheets`）中按 `data-webhelp-theme` 区分浅色与深色。高亮只在文字背后着色，不插入元素，不改变排版，关闭后与原文逐像素一致。
- 高亮范围保存点击层绑定的原文本节点（`StaticRange`），原网页的表格增强移动节点后仍标在原处。两组重叠时定义优先，与点击层的命中顺序一致。
- 选择与主题一样是本浏览器的阅读偏好，保存在 `localStorage`（`anna.linkMarks`，默认关闭时不存储），同源标签页同步，不写入 URL 或历史；存储被禁止时仍可在当前页切换。阅读壳在 `initialize` 中带上当前选择，切换时向已载入的正文发送 `link-marks` 消息。
- 浏览器不支持 CSS 自定义高亮时不显示该开关，链接照常可用。

正文占满其余除目录之外的空间；收起目录后使用完整窗口宽度。页面标题在原文中呈现；阅读栏的位置路径以当前层级写出页名，供定位和跳转，标签页标题同样写出页名。阅读壳不再添加第二层纸张边距、重复标题或固定底栏，正文自己的行长、边距与表格布局由原版样式决定。

连续阅读时，页与页之间的界线画在原文的纸面上：页脚、未加载区间与“已到本章节末尾”沿用原文正文的栏宽（至多 1160px 居中）、左右边距与纸面颜色，宽屏上前后两页因此连成同一张纸。原文的主题色由 `--anna-source-*` 镜像 `webhelp-topic.css` 的 `--topic-*` 取值，阅读壳不跨文档读取样式。每页末尾有一枚小装饰，如同印刷书的页脚：两段渐隐短线夹着星形与该页的“页序／总页数”，下方留白略大于原文的底边距，使页码贴近它所结束的一页。最后一页不写页码，由“已到本章节末尾”使用同一枚装饰收束，所以每页恰好编号一次，第一页之前也不需要页眉。短线保持短，免得与原文 `h2` 上方的整行分隔线叠成两道。页脚只是视觉标记（`aria-hidden`）；每页开头另有一个只给读屏的起点（`.book-page-start`），读出页序与页名，手动接续后焦点移到这里。视口顶端落在某页页脚内时，当前页算作下一页，与读者的去向一致。未加载区间不加边框，只写明区间并给出接续按钮。

原版 WebHelp 壳还会给正文加载主题与对比度修复资源，仅加载裸 HTML 不能重现原版阅读效果。构建层在 `presentation_resources` 中列出当前快照实际具备的 `webhelp-topic.css`、`content-enhance.css/js` 和 `webhelp-contrast.js`；bridge 按原版资源 ID 补入缺少的文件，并同步 `data-webhelp-theme`。这层复用正文呈现资源，不加载上游导航壳，也不修改镜像文件。

bridge 在 DOM 及补入的样式可用后报告文档就绪，让文字先于大图显示；后续高度变化只更新布局，不重复执行初次定位。嵌入正文的点击层不再自行滚动文档，独立打开原貌正文时保留原有定位。点击层先统一测量文字范围，再更新命中区域，避免每条链接的读写交错反复触发布局。正文资源使用内容哈希 ETag 和 `private, no-cache`，每次校验当前发布快照后可返回 304，共享 CSS、脚本和图片不必反复传输；重建后仍返回 409，要求重启服务。

界面文案集中在 `reader-labels.js`，同步维护中英文。操作说明见[阅读操作](../USAGE.md#阅读操作)，测试与实际走查见[链接版验证记录](../tests/linked-book-validation.md)。

## 施法规则链

`knowledge.js` 提供双语施法条件控件和规则链阅读；`detail.js` 将它作为独立阅读标签，保留已有正文、字段、关系和审核入口。`casting` 查询参数携带单个 JSON 条件组，所有字段约束同一授予、法术和使用分支；`tab=chain` 与 `chain_spell` 保存阅读位置，不表示角色选择。API 返回未解析部分和审核状态，界面不自行重做名称解析。数据结构见 [MODEL.md](../MODEL.md#施法规则链)，操作见 [USAGE.md](../USAGE.md#施法链查询与审核)。
