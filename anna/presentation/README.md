# 查询与阅读的消费边界

分析层需要调整提取方式和内部存储，Anna 与 Stella 则需要稳定的查询、定位与阅读行为。`presentation` 从已发布的数据生成消费模型，使分析实现的变化集中在读取与映射处，不直接传播到浏览器。它不重新提取原文、不重放审核，也不写入知识或审核决定。

## 职责

| 模块 | 回答的问题 |
| --- | --- |
| `catalog.py` | 当前条件命中哪些条目，如何排序、叠放版本、计数和导出？ |
| `knowledge.py`、`reading.py` | 同一分支如何查询，规则链怎样保留起点、关系、限定与局部效果位置？ |
| `references.py` | 当前发布快照中有哪些有效引用、审核结果与缺失定义？ |
| `layout.py`、`reader.py` | 如何从条目回到原文排版、目录页面与定义锚点？ |
| `contracts.py` | 哪些存储字段进入现有的条目、知识、选项与引用响应？ |

HTTP 路由、状态码、下载头和快照切换由 `anna/server/` 负责；规则链与引用的命令行读取也使用相同的只读消费模型。`anna/knowledge/repository.py` 保留提取、构建、审计和标注写入，CLI 的 `chain` 命令调用本包；`anna/catalog/query.py` 仍提供独立的只读数据分析查询。来源上下文位于 `anna/knowledge/context.py`，规则关系索引生成位于 `rule_index.py`，供构建与审计共同使用。

## 保持什么稳定

消费契约包括响应字段及其含义、缺失与空值、数组顺序、筛选计数、同名版本叠放、条目与局部效果标识、证据范围、解析和审核状态。查询参数、错误响应、HTML 中的批注和引用属性、链接版的 `anna-bindings`、定义锚点及阅读消息协议同样属于边界。仅保持 JSON 的字段名称不足以保持阅读体验。

`contracts.py` 明确选择条目和知识记录的公共字段，并为授予、使用分支、效果和选项建立投影。新增存储字段不会自动进入这些响应。条件表达式、数量、证据、字段映射及其他语义 JSON 是已公开的结构化内容，按原值复制；它们的结构若改变，同样需要在适配处转换并验证消费契约。

规则链与知识导出继续使用既有 `schema: 2`。消费版本由本包维护，不随提取模型的版本常量自动变化；其他存储版本必须增加明确适配，不能伪装成结构 2。效果查询的公开取值由 `anna/knowledge/query_schema.py` 定义，查询与物化索引共用，提取器新增效果种类不会自动扩展界面查询范围。此边界不新增旧路径转发或双套提取实现。

本轮保留原有身份与快照规则：同一快照内的链接和恢复行为不变；快照变化后，浏览器只保留查询条件，清除依赖旧快照的位置。跨快照身份迁移属于独立的数据能力，不能通过复用旧快照摘要绕过校验。

## 验证与后续修改

`tests/fixtures/presentation-*.json` 保存边界拆分前的只读数据、查询与规则链响应，以及原文排版和阅读绑定。`tests/test_presentation_contracts.py` 直接恢复冻结的 SQLite 行，不运行提取器，核对完整响应、顺序、CSV、HTTP 错误和下载、HTML 定位及拒绝情形；另检查内部字段隔离和服务导入不加载知识提取或审核命令。夹具只固定消费行为，不代替全库审计与实际语料检验。

调整分析实现时，先在相同冻结输入上运行契约测试，再运行完整构建与 `make check` 验证全库覆盖与一致性。运行命令统一见 [USAGE](../../USAGE.md)。原文更新或有依据的规则修订可以改变结果，但应先解释差异，再修改对应预期；不要用本次输出直接重录所有夹具。浏览器回归仍需验证 Anna、Stella、共享状态、键盘焦点和不同窗口宽度。
