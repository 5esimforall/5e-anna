# 第一批验收清单：获取与施法

第一批交付的是可查、可读、可审核、可导出的施法规则链。验收以读者问题为单位，分别核对获取、使用、判定、结果、通则与例外；解析出更多条目不能替代某个环节的交付。本清单固定首批的代表性机制和拒绝边界，开发顺序由 [ROADMAP](../ROADMAP.md) 管理，实际执行结果保存在[验证记录](casting-chain-validation.md)。

## 验收口径

每个问题均须提供以下证据：

1. **独立原文预期。** 从只读镜像核对版本、所属、句段及限定；先写预期，再运行解析。条目改名不能改变机制识别。同名、不同代际与竞争定义不得混用。
2. **结构化答案。** 查询、阅读、审核和导出消费同一有效记录。取得资格、持续启用、使用分支、检定及结果、持续与解除分别表达；未知不改写为没有或无限制。
3. **对应拒绝情形。** 未知限定、缺失目标、竞争候选、非法字段、依据失效均有回归；条件不得跨分支、跨效果或跨目标拼接。
4. **双向阅读。** 从获取者进入效果和通则，再返回起点；保存证据、候选状态、分支及局部位置。刷新、前进后退和导出保留同一个问题。
5. **发布验证。** 全量单元/API、浏览器和数据审计通过；原文更新、重新载入与重建使用临时夹具验证。实机验收由用户执行，自动化通过不代替该项。

“已解析”“部分解析”“待核”和“已否决”按环节报告。通则身份尚无充分证据时，可验收候选、拒绝任意选择及审核流程；不能将存在候选报告为身份已确定。人工采用不补全未解析语义。

## 固定边界

本批要求上述问题的关键环节可用，并保留其未解析及身份待核边界。跨段检定以明确目标引用和有证据的句段范围为依据；具名目标、嵌套区域和跨条目检定先以结构夹具验证引用及拒绝边界，再按有共同句式的原文推广。连续计数、重置和阶段转换同样先验证模型与消费端，不以声称能解析任意句式作为第一批完成条件。

全库持续扫描用于发现同类缺口；第一批不要求全库语义解析完毕、人工审核清零、任意职业整张角色卡可计算，或游戏规则自动结算。表格驱动的多层选择以 B1-02 至 B1-04 的路径为边界；其他工具、活动、怪物动作及子系统的全面推广属于后续批次。新增发现须映射到现有验收问题；确需扩大首批目标时先说明新增问题与工作量，不通过增加样本悄悄改变完成条件。

固定边界不把当前缺口改称支持：清单要求但尚未交付的能力继续列在 ROADMAP；未完成的问题不能因其缺口已显示而整体通过。每次验证记录按 B1 编号说明本轮完成的环节、未完成项及实际执行的检查。
